# Shared domain slice

The menu in `src/menu.ts` is **synthetic design preview content**. It is not the restaurant's approved menu. Every fixture is marked `fixture: true`; `MENU_CONTENT_STATUS` and `MENU_NOTICE` are exported for presentation. Fixture data must not be promoted to production merely by removing a banner.

`src/lunch-menu.ts` separately contains the **37 owner-supplied lunch dishes** at their initial $13.99 CAD base price. It exports `lunchMenuItems`, `lunchCategories`, `lunchMenuDetails` and `isLunchMenuItem`. Source heat/peanut markers, noon–3 p.m. holiday-excluded service wording, included sides and the $2.50 fried-rice/$1.00 dry upgrades are preserved. Listed styles and inclusions use required modifier groups. Lunch entries also retain `fixture: true` to block live pricing until payment/tax/fulfillment configuration is approved; the flag does not mean their names and prices were invented. The shared local catalog includes lunch plus the legacy nine items, while public lunch views and the editor select the lunch subset.

Local catalog overrides support current price, image/photo-or-cutout presentation and heat/peanut markers. Current catalog values drive the lunch menu and cart pricing; changes are browser-local and do not establish a production server authority. The lower homepage food stories are editorial content independent of the catalog. Any retained `featured` data is unused by those stories and is not a homepage editor control. Missing peanut markers must never be rendered as an allergen-free claim.

`priceLine` revalidates selections against a trusted catalog. `priceCart` adds deterministic cent arithmetic, a five-minute quote expiry, a copied line/tax snapshot, and an explicit preview/approval gate. Its single tax group is an arithmetic building block, not a complete Ontario tax determination engine. Accountant-approved classifications, rebate conditions, fees and refund allocation examples remain required before accepting payment.

`quotePromo(code, selections, catalog, { preview: true })` demonstrates a single promo code against food repriced from the trusted catalog. WOK10 gives 10% off a food subtotal of at least $20, capped at $15; DEMO5 gives $5 off at $35. Both are explicitly synthetic, cannot run without preview mode, and return `productionApplicable: false`. The result excludes tax and tips. Live eligibility, redemption limits, approval and tax treatment remain server responsibilities; these fixtures have no invented expiry policy.

Payment, fulfillment and printing have separate functions. `transitionFulfillment` validates the transition graph only; API authorization, verified payment eligibility, reservation checks, version checks, row locking and audit records remain application/database responsibilities. Do not expose it directly as an unauthenticated mutation endpoint.

Toronto scheduling rejects daylight-saving gaps and requires an explicit choice for repeated local times. `isSlotBookable` tests capacity and checkout/preparation lead time only. Approved business hours, closures, booking horizon and durable reservation locking must be applied by the server before offering or reserving a slot.

The print helpers distinguish transport delivery from device completion and keep uncertain outcomes in `UNKNOWN`. They do not replace a durable local journal, fenced server dispatch gate, physical printer qualification or a manager's audited reprint workflow.

Run `pnpm test` from the repository root. Test names identify the corresponding SRS requirements, but these unit tests do not establish complete end-to-end or hardware acceptance for those requirements.

Verified on 18 November 2026: `pnpm test` passed all 33 tests (9 domain, 6 lunch, 6 promo, 7 browser-local catalog and 5 cart tests), and `pnpm exec tsc -p tsconfig.packages.json --noEmit` passed with no diagnostics. Lunch tests check source coverage, terms, markers, required choices, upgrade cents and live-pricing rejection. Catalog tests cover image/field validation, storage limits/failures, stable snapshots, tab notifications, reset, current prices and stored flags. Cart regressions cover unavailable-line persistence, failed-write fallback, recovered cross-tab reads, blocked reads and validated repricing. These checks cover the shared packages and local storage boundary, not story-card interactions, connected payments, server menu persistence, API authorization or physical printers.
